EMC state-feedback redesign

Applied to the real reference panel and rendered from the actual Basalt code (headless, no Minecraft). Every control/status is a subpixel-outlined box, colour-coded by role. Clean, non-overlapping, each element its own complete outline.

◆ Current direction: 1-row end-cap chips

A 1-row dark-gray chip with a font-colour label and a colored subpixel stripe at each end that codes the role: green/red = switch state · orange = stateless action · blue = drilldown / picker / scratchpad · orange↔gray checkered = status/readout (with a red/green state dot). All of emc_config fits the original 17-row region — no split change needed.

Earlier option: the underline style

left: underline chip (2-row) — recommended · right: left stripe (1-row) — merges without gaps

The 3-row box below is a full surround (the honest floor for outlining all four sides). For dense menus that's too heavy, so here's the lighter alternative: a 2-row underline chip — text with a thin colored subpixel line under it. Same colour language (orange action, gray readout, red/green state), but the underline row also separates stacked items, so ~13 controls fit in ~14 rows. Same treatment covers buttons, readouts, and fields. My recommendation is to switch EMC and the rollout to this.

The colour language

State (green / red)

A switchable button or status: green=on, red=off. Radio groups keep one green at a time.

Action (orange)

A stateless button — BACK, PULSE±, CAL FUEL, a picker. Actionable, no on/off state.

Readout (gray)

A status group-box with no action and no switchable state — Pulse: 250ms, Int: 5m 30s.

Disabled (light gray)

An inert / gated control. Light-gray outline + text, so it never reads as an orange action.

The primitive & radio behaviour

toggles flip green↔red on press · radio group keeps one green · status boxes group a label with its value
